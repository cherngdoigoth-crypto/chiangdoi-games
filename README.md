# ระบบบริหารคะแนนการแข่งขันกีฬาเชิงดอยเกมส์ ครั้งที่ 26 ประจำปีงบประมาณ 2570

เว็บแอปบันทึกคะแนน ตรวจสอบ อนุมัติ และประกาศผลแบบเรียลไทม์ สำหรับการแข่งขันวันที่ 7–8 พฤศจิกายน 2569 ณ สนามกีฬาเทศบาลตำบลเชิงดอย

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ | React 19 + TypeScript + Vite 7 + Tailwind CSS 3 (โฮสต์บน **Netlify**) |
| API / ตรรกะฝั่งเซิร์ฟเวอร์ | **Google Apps Script** (เขียนด้วย TypeScript รวมเป็นไฟล์เดียวด้วย esbuild) |
| ฐานข้อมูล | **Google Sheets** (1 แท็บต่อ 1 ตาราง) |
| ทดสอบ | Vitest (unit + integration + ทดสอบไฟล์ Apps Script บนชีตจำลอง) |

> ข้อมูลจากสูจิบัตรและรายการสิ่งที่ผู้จัดต้องยืนยันก่อนใช้งาน อยู่ใน [`docs/ANALYSIS.md`](docs/ANALYSIS.md) — **อ่านก่อนเปิดใช้งาน**

## 1. ความสามารถหลัก

- **ผลรายกีฬา**: กีฬาพื้นบ้าน 12 รายการ (บันทึกอันดับ 1–3), ยิงลูกโทษ (น็อคเอาท์), ฟุตบอล 7 คน และเปตอง (บันทึกผลรายนัด ตารางคะแนนในสาย ผลจับฉลากเมื่อคะแนนเท่ากัน)
- **การประกวด 4 รายการ** ให้คะแนนตามเกณฑ์ 5 ข้อ รวม 50 คะแนน เลือกได้ว่า "ผู้บันทึกคนเดียว" หรือ "คณะกรรมการ" (กรรมการแต่ละคนมีใบคะแนนของตัวเอง กรอกพร้อมกันได้)
- **ถ้วยคะแนนรวม** ชนะเลิศ 3 / ที่ 2 ได้ 2 / ที่ 3 ได้ 1 เฉพาะกีฬาพื้นบ้านและยิงลูกโทษที่ **อนุมัติแล้ว** คำนวณที่เซิร์ฟเวอร์ แสดงรายละเอียดว่าได้คะแนนจากรายการใด
- **ขั้นตอนผล**: ยังไม่เริ่ม → กำลังดำเนินการ → รอตรวจสอบ → อนุมัติแล้ว → ประกาศผลแล้ว → ล็อกผล พร้อมส่งกลับแก้ไข/ปฏิเสธ/ยกเลิกประกาศ (ต้องระบุเหตุผล)
- **ซ่อน/เปิดเผยผล** ฝั่งเซิร์ฟเวอร์: ข้อมูลที่ยังไม่ประกาศ **ไม่ถูกส่งออก** ไปยังหน้าสาธารณะเลย (ไม่ใช่ซ่อนด้วย CSS)
- **ป้องกันการแก้ไขชนกัน**: ทุกการเขียนอยู่ภายใต้ `LockService` และตรวจเลขเวอร์ชัน (optimistic concurrency) ถ้ามีคนแก้ก่อน ระบบปฏิเสธและแจ้งให้โหลดข้อมูลล่าสุด
- **ประวัติการเปลี่ยนแปลง (Audit log)** ทุกการบันทึก/เปลี่ยนสถานะ/ตั้งค่า/จัดการผู้ใช้ เก็บในแท็บ `AuditLog` (ผู้ทำ เวลา รายละเอียด เหตุผล)
- **เรียลไทม์ทุกอุปกรณ์**: ทุกเครื่องดึงข้อมูลเป็นระยะ (ค่าเริ่มต้น 4 วินาทีสำหรับเจ้าหน้าที่, 8 วินาทีสำหรับผู้ชม) โดยใช้เลข revision — ถ้าไม่มีอะไรเปลี่ยน เซิร์ฟเวอร์ตอบสั้น ๆ ไม่อ่านชีต
- **จอแสดงผลสาธารณะ** `/display` สำหรับโปรเจกเตอร์/จอ LED ตัวอักษรปรับตามขนาดจอ ใช้สีประจำหมู่บ้าน
- **รายงาน** ผลรายกีฬา การประกวด ถ้วยรวม ประวัติ — ส่งออก CSV (เปิดใน Excel ภาษาไทยถูกต้อง) และพิมพ์/บันทึกเป็น PDF

### บทบาทผู้ใช้

| บทบาท | ทำอะไรได้ |
|---|---|
| Super Admin | ทุกอย่าง รวมถึงสร้าง/แก้บัญชีผู้ดูแล ปลดล็อกผล เปลี่ยนเงื่อนไขถ้วยรวม |
| Admin | จัดการรายการ เกณฑ์ ผู้ใช้ (ยกเว้นผู้ดูแล) มอบหมายงาน เผยแพร่/ยกเลิก/ล็อกผล |
| Scorekeeper (ผู้บันทึกคะแนน) | บันทึกคะแนนเฉพาะรายการที่ได้รับมอบหมาย / เป็นกรรมการให้คะแนน |
| Result Reviewer (ผู้ตรวจสอบผล) | ตรวจสอบ อนุมัติ ส่งกลับ ปฏิเสธ (อนุมัติผลที่ตนเองส่งไม่ได้) |
| Public Viewer | ไม่ต้องเข้าสู่ระบบ เห็นเฉพาะผลที่ประกาศแล้ว (บัญชีบทบาท "ผู้ชม" ใช้ดูข้อมูลภายในแบบอ่านอย่างเดียว) |

## 2. โครงสร้างโปรเจกต์

```
shared/domain/        ตรรกะกลาง (ใช้ทั้งเว็บและ Apps Script): ชนิดข้อมูล ข้อมูลตั้งต้นจากสูจิบัตร การคำนวณคะแนน สถานะ
server/src/api.ts     API ทั้งหมด (สิทธิ์ ตรวจข้อมูล ขั้นตอนผล ถ้วยรวม audit) — ไม่ผูกกับ Google Sheets
server/src/store.ts   อินเทอร์เฟซที่เก็บข้อมูล + MemoryStore (ใช้ทดสอบ)
server/src/gas/       จุดเข้า Apps Script (doGet/doPost/setup/backup) และ SheetStore บน Google Sheets
server/src/devServer.ts  เซิร์ฟเวอร์จำลองสำหรับพัฒนาในเครื่องเท่านั้น
server/dist/          ผลลัพธ์สำหรับ Apps Script: Code.js + appsscript.json
src/                  หน้าเว็บ React (pages/, components/, state/, lib/)
netlify/functions/    พร็อกซีข้อมูลสาธารณะผ่าน CDN ของ Netlify (ไม่บังคับ)
tests/                domain.test.ts, api.test.ts, gas-bundle.test.ts
docs/ANALYSIS.md      สรุปสูจิบัตรและข้อมูลที่ต้องยืนยัน
```

### ตารางใน Google Sheets

| แท็บ | เก็บอะไร |
|---|---|
| `Villages` | 10 หมู่บ้าน สี ลำดับขบวน |
| `Competitions` | รายการแข่งขัน สถานะ รางวัล ผู้มีสิทธิ์ การนับถ้วยรวม |
| `Criteria` | เกณฑ์การให้คะแนนการประกวด + การยืนยัน |
| `Assignments` | ผู้บันทึกหลักและกรรมการของแต่ละรายการ |
| `Matches` | ตารางและผลรายนัด |
| `Scores` | คะแนนที่ผู้บันทึกกรอก (ฉบับร่าง/ส่งแล้ว) พร้อมเวอร์ชัน |
| `JudgeSheets` | ใบคะแนนของกรรมการแต่ละคน |
| `Results` | ผลที่อนุมัติแล้ว + เวลาประกาศ (คอลัมน์ `summary` อ่านง่าย) |
| `Users` | บัญชีผู้ใช้ (เก็บรหัสผ่านแบบแฮช SHA-256 1,000 รอบ + salt ไม่มีรหัสจริง) |
| `Sessions` | session ที่เข้าสู่ระบบ (เก็บเฉพาะค่าแฮชของ token อายุ 12 ชั่วโมง) |
| `Settings` | ซ่อน/เปิดถ้วยรวม ประกาศอัตโนมัติ กติกาตัดสินเสมอ |
| `AuditLog` | ประวัติการเปลี่ยนแปลงทั้งหมด |

> **อย่าแก้ข้อมูลในชีตด้วยมือระหว่างการแข่งขัน** (ระบบจะไม่บันทึกประวัติ และอาจทำให้เลขเวอร์ชันไม่ตรง) ให้แก้ผ่านหน้าเว็บเท่านั้น แชร์สเปรดชีตให้เฉพาะผู้ดูแลระบบ

## 3. ติดตั้งและตั้งค่า

### 3.1 สิ่งที่ต้องมี
- Node.js 22 ขึ้นไป
- บัญชี Google (แนะนำบัญชีของหน่วยงาน) และบัญชี Netlify

```bash
npm install
npm test          # ทดสอบทั้งหมด
npm run build:gas # สร้าง server/dist/Code.js
```

### 3.2 สร้างฐานข้อมูลและ API บน Google

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `เชิงดอยเกมส์ 26 - ฐานข้อมูล`
2. เมนู **ส่วนขยาย → Apps Script** (จะได้โปรเจกต์ที่ผูกกับชีตนี้)
3. นำโค้ดขึ้น เลือกวิธีใดวิธีหนึ่ง
   - **คัดลอกวาง**: ในตัวแก้ไข Apps Script เปิด *Project Settings* → ติ๊ก "Show appsscript.json" แล้ววางเนื้อหา `server/dist/appsscript.json` จากนั้นวางเนื้อหาทั้งหมดของ `server/dist/Code.js` ลงในไฟล์ `Code.gs`
   - **ใช้ clasp**: `npx clasp login` → คัดลอก `server/.clasp.json.example` เป็น `server/.clasp.json` ใส่ Script ID (Project Settings → IDs) → `npm run push:gas`
4. ตั้ง **Script Properties** (Project Settings → Script Properties)
   - `ADMIN_USERNAME` = ชื่อผู้ใช้ Super Admin คนแรก (อังกฤษตัวเล็ก)
   - `ADMIN_PASSWORD` = รหัสผ่านชั่วคราว (≥ 8 ตัว มีตัวเลขและตัวอักษร) — ระบบจะลบค่านี้ทิ้งหลัง setup และบังคับเปลี่ยนรหัสเมื่อเข้าสู่ระบบครั้งแรก
   - `BACKUP_FOLDER_ID` (ไม่บังคับ) = ID โฟลเดอร์ Google Drive สำหรับไฟล์สำรอง
5. เลือกฟังก์ชัน **`setup`** แล้วกด **Run** → อนุญาตสิทธิ์ (Sheets, Drive สำหรับสำรองข้อมูล, Triggers) ระบบจะสร้างแท็บทั้งหมดและข้อมูลตั้งต้นจากสูจิบัตร (รันซ้ำได้ ไม่เขียนทับข้อมูลที่มีอยู่)
6. **Deploy → New deployment → Web app**
   - Execute as: **Me** (บัญชีเจ้าของชีต)
   - Who has access: **Anyone** (การเข้าถึงข้อมูลควบคุมด้วยระบบบัญชีของแอปเอง — ผู้ไม่ได้เข้าสู่ระบบเห็นแค่ผลที่ประกาศแล้ว)
   - คัดลอก URL ที่ลงท้ายด้วย `/exec`
7. (แนะนำ) รันฟังก์ชัน `installBackupTrigger` ครั้งเดียว เพื่อสำรองข้อมูลทุกชั่วโมง

> ทุกครั้งที่แก้โค้ด API ต้อง **Deploy → Manage deployments → Edit → New version** เพื่อให้ URL เดิมใช้โค้ดใหม่

### 3.3 นำหน้าเว็บขึ้น Netlify

1. นำโปรเจกต์ขึ้น GitHub แล้วเลือก *Add new site → Import from Git* บน Netlify (ค่าใน `netlify.toml` ตั้งคำสั่ง build ไว้แล้ว) หรือใช้ `npx netlify deploy --prod`
2. ตั้ง **Environment variables** ใน Netlify (Site configuration → Environment variables)

| ตัวแปร | ค่า |
|---|---|
| `VITE_API_URL` | URL `/exec` ของ Apps Script |
| `VITE_POLL_STAFF_MS` | ความถี่ดึงข้อมูลของเจ้าหน้าที่ (มิลลิวินาที) ค่าเริ่มต้น 4000 |
| `VITE_POLL_PUBLIC_MS` | ความถี่ของผู้ชม ค่าเริ่มต้น 8000 |
| `VITE_PUBLIC_PROXY` | `true` เพื่อให้ผู้ชมดึงข้อมูลผ่าน Netlify CDN (แนะนำเมื่อผู้ชมเยอะ) |
| `APPS_SCRIPT_URL` | URL `/exec` เดียวกัน (ใช้โดย Netlify Function เมื่อเปิด `VITE_PUBLIC_PROXY`) |

3. Deploy ใหม่หลังตั้งค่าตัวแปร (ค่า `VITE_*` ถูกฝังตอน build)
4. ไม่มี secret ใดอยู่ในหน้าเว็บ — URL ของ Apps Script เป็นข้อมูลสาธารณะ สิทธิ์ทั้งหมดตรวจที่เซิร์ฟเวอร์

### 3.4 พัฒนาในเครื่อง

```bash
npm run dev:api                                  # API จำลองที่ http://localhost:8787 (admin / Admin1234)
echo "VITE_API_URL=http://localhost:8787" > .env.local
npm run dev                                       # หน้าเว็บที่ http://localhost:5173
```
API จำลองใช้ตรรกะชุดเดียวกับ Apps Script แต่เก็บข้อมูลในไฟล์ `.dev-data.json` — **ห้ามใช้ในการแข่งขันจริง**

## 4. ก่อนวันแข่งขัน (Checklist)

1. เข้าสู่ระบบด้วย Super Admin → เปลี่ยนรหัสผ่าน
2. **ผู้ใช้งาน**: สร้างบัญชีให้ทุกคน (ห้ามใช้รหัสร่วมกัน) แจ้งรหัสชั่วคราวเป็นรายบุคคล
3. **จัดการการแข่งขัน** ทุกรายการ: ตรวจชื่อ เวลา รางวัล ผู้มีสิทธิ์ แล้วมอบหมายผู้บันทึกหลัก
4. การประกวด 4 รายการ: เลือก "ผู้บันทึกคนเดียว" หรือ "คณะกรรมการ" → **กรอกคะแนนเต็มรายข้อให้รวม 50** → (คณะกรรมการ) เลือกวิธีรวมเฉลี่ย/รวม → กด **ยืนยันเกณฑ์** — สูจิบัตรไม่ได้ระบุคะแนนรายข้อ ต้องใช้ค่าที่คณะกรรมการตกลง
5. **เผยแพร่ผล**: เลือกกติกาตัดสินเมื่อคะแนนถ้วยรวมเท่ากันตามมติผู้จัด (สูจิบัตรไม่ได้ระบุ) ตั้งว่าจะเปิดเผยถ้วยรวมเมื่อใด
6. ยิงลูกโทษ: เพิ่มคู่รอบถัดไปตามที่ผู้จัดยืนยัน (สูจิบัตรหน้า 23 ระบุคู่รอบรองไม่สอดคล้องกับผัง)
7. กด **เปิดรับคะแนน** เมื่อพร้อม
8. ซ้อมด้วยโทรศัพท์จริง 2–3 เครื่อง + จอแสดงผล + ทดลองปิด Wi-Fi แล้วเปิดใหม่ (ดูหัวข้อ 6)
9. รัน `backupNow` ใน Apps Script หนึ่งครั้ง และตรวจว่าไฟล์สำรองเกิดขึ้นใน Drive

### ขั้นตอนระหว่างแข่งขัน
ผู้บันทึกกรอกผล → **บันทึกฉบับร่าง** (ข้อความ "บันทึกแล้ว" ขึ้นหลังเซิร์ฟเวอร์ยืนยันเท่านั้น) → **ส่งผลเพื่อตรวจสอบ** → ผู้ตรวจสอบ **อนุมัติ** หรือ **ส่งกลับแก้ไข** พร้อมเหตุผล → ผู้ดูแล **ประกาศผล** (หน้าสาธารณะและจอแสดงผลอัปเดตเองภายในไม่กี่วินาที) → **ล็อกผล** เมื่อสิ้นสุด

ถ้าพบผลผิดหลังประกาศ: **ยกเลิกการประกาศ** (ระบุเหตุผล) → **เปิดแก้ไขผลอีกครั้ง** → ผู้บันทึกแก้ → ส่ง → อนุมัติ → ประกาศ ถ้วยรวมคำนวณใหม่อัตโนมัติ

## 5. ความปลอดภัย

- ทุกคำขอที่เปลี่ยนข้อมูลตรวจ session + บทบาท + การมอบหมาย **ที่ Apps Script** ไม่เชื่อค่าจากหน้าเว็บ
- รหัสผ่านเก็บเป็นแฮช (salt + SHA-256 1,000 รอบ) ใส่ผิด 5 ครั้งล็อกบัญชี 10 นาที บัญชีใหม่และบัญชีที่ถูกรีเซ็ตต้องเปลี่ยนรหัสก่อนใช้งาน
- session หมดอายุใน 12 ชั่วโมง ปิดบัญชีหรือเปลี่ยนบทบาทแล้ว session เดิมถูกยกเลิกทันที
- หน้าสาธารณะได้รับเฉพาะผลที่ประกาศแล้ว (ทดสอบใน `tests/api.test.ts`)
- ผู้ส่งผลอนุมัติผลของตนเองไม่ได้ การเปลี่ยนเงื่อนไขถ้วยรวมต้องเป็น Super Admin พร้อมเหตุผล
- Netlify ตั้ง Content-Security-Policy และ header ความปลอดภัยไว้ใน `netlify.toml`
- แชร์ Google Sheet ให้เฉพาะผู้ดูแลระบบ (คนที่เปิดชีตได้จะเห็นข้อมูลทั้งหมด)
- ข้อจำกัด: Apps Script ไม่มี bcrypt/argon2 จึงใช้ SHA-256 แบบวนรอบ — ใช้รหัสผ่านที่ไม่ซ้ำกับบริการอื่น

## 6. สำรองและกู้คืนข้อมูล

- **อัตโนมัติ**: `installBackupTrigger` คัดลอกสเปรดชีตทั้งไฟล์ทุกชั่วโมงไปยัง `BACKUP_FOLDER_ID`
- **ทันที**: รัน `backupNow` ใน Apps Script
- **ประวัติเวอร์ชันของ Google Sheets**: ไฟล์ → ประวัติเวอร์ชัน
- **กู้คืน**: เปิดไฟล์สำรอง → คัดลอกแท็บที่ต้องการกลับมาแทนที่ หรือกำหนด Script Property `SPREADSHEET_ID` ให้ชี้ไปที่ไฟล์สำรองแล้ว Deploy เวอร์ชันใหม่
- ส่งออก CSV จากหน้า "รายงาน" เก็บไว้ภายนอกได้อีกชั้น

## 7. ข้อจำกัดของ Apps Script และคำแนะนำ

- Apps Script ไม่รองรับ push แบบ WebSocket ระบบจึงใช้การดึงข้อมูลเป็นระยะ ความหน่วงสูงสุด ≈ ค่า `VITE_POLL_*` + เวลาตอบกลับ (ปกติ 1–3 วินาที)
- Apps Script รันพร้อมกันได้จำกัด (ประมาณ 30 คำขอ) — เมื่อมีผู้ชมจำนวนมาก ให้เปิด `VITE_PUBLIC_PROXY=true` เพื่อให้ Netlify CDN แคชข้อมูลสาธารณะ 4 วินาที และเพิ่ม `VITE_POLL_PUBLIC_MS` เป็น 10000 ขึ้นไป ฝั่ง Apps Script เองก็แคชข้อมูลสาธารณะตามเลข revision ด้วย `CacheService`
- การบันทึกแต่ละครั้งใช้เวลาประมาณ 1–3 วินาที (ล็อกทั้งระบบเพื่อกันข้อมูลชน) เหมาะกับผู้บันทึกหลักไม่เกินราว 20–30 คนพร้อมกัน
